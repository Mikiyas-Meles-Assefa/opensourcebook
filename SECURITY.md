# Security

## Reporting a problem

Please report a security problem privately, not in a public issue. Use GitHub's private vulnerability reporting: on the repository, `github.com/Mikiyas-Meles-Assefa/opensourcebook`, open the **Security** tab and choose **Report a vulnerability**. Say what you found, how to reproduce it, and which version or commit and which system you were on.

If the Security tab does not show that option, open an ordinary issue that says only that you have a security problem to report, with no details, and a private way to talk will be arranged.

## What to expect

One person maintains Open Sourcebook. You will get a reply as soon as they can, and there is no promised time. They will say whether they could reproduce it and what they plan to do. A fix is made in private, then released, and the report is made public afterwards with credit to you if you want it. Please give the fix time to reach people before you write about the problem in public. There is no bounty.

## What is in scope

- **The four programs on a person's computer**: the engine, the web app, the agent connector and the scenes service, and the launcher that starts them. How they handle secrets, addresses, files and the sandbox.
- **The phone's door** (`cli/door.ts`): pairing, the device cookie, and what a paired or unpaired device can reach.
- **The installer** (`install/`): the two scripts served at `opensourcebook.app`, the npm package `opensourcebook`, what they download and where they write.

For example: a way to reach a program from another device, a way for a source or a page to make the agent read outside its folder, a secret that is written somewhere it should not be, or an install that runs or writes something it does not say.

## Not covered

What your agent or its provider does under their own terms, and the software Open Sourcebook depends on (report those to their makers). Open Sourcebook is early and one person's work, so please do not rely on it to run anything you could not afford to have go wrong.

## How Open Sourcebook is built, in plain words

- **It runs on your computer.** The engine, the web app, the agent connector and the scenes service are programs on your own computer. Open Sourcebook has no server that receives your files, and there is no Open Sourcebook account.
- **It listens on this computer only, with one door you open yourself.** Each program, and the launcher's own control, listens on `127.0.0.1`, so another device on your network cannot reach it. The one exception is the phone's door (`cli/door.ts`), which listens on your home network only while you have turned "Open on your phone" on. The debugger ports of the engine and of the web app's runtime are shut; they open, on `127.0.0.1`, only when someone developing Open Sourcebook sets `OPENSOURCEBOOK_ENGINE_INSPECTOR=1` or `OPENSOURCEBOOK_WEB_INSPECTOR=1`.
- **Only the browser Open Sourcebook opened can use it.** The web app's proxy holds the engine's token, so it serves the engine only to this computer's browser that Open Sourcebook let in, with a key made new at each start and kept in a cookie scripts cannot read and other sites cannot send. Starting it opens the browser with an address that lets it in once; `opensourcebook open` (`npm run open` in a clone) makes another. A browser where the address was typed by hand, another program, or another person's account on this computer gets a page that says how to open Open Sourcebook, and nothing of your projects.
- **A phone pairs once and never manages pairing.** Each device pairs with a one-time code from a QR code and gets its own token in a cookie, kept as a hash in `state/devices.json` in the app data folder; a device unused for thirty days must pair again. The door decides on the same path the web app reads (any other spelling of a path is refused), and everything it passes on is marked with its own key, so the web app never lets a phone see the pairing code, pair another device, remove one or turn the door off, however the request is spelled. Those are for this computer's browser only.
- **What Open Sourcebook fetches from the web is checked, address by address.** Open Sourcebook fetches what your sources point at (a link source and the pictures and files in it), and the video agent's tools open pages, pictures, archives, PDFs and videos. Every address a source or a model names goes through one check (`common/addresses.ts`): only public addresses are opened, never this computer, your own networks or the cloud metadata address, in any spelling of the address. In the scenes service the name is looked up once and the connection goes to the address that was checked, every redirect is checked again, and its headless Chrome, ffmpeg and yt-dlp reach the web only through the same check. The engine checks every address and every redirect too, but it cannot choose where its runtime connects, so on your computer a name whose answer changes between the check and the connection, or that this computer resolves differently from the public internet (a hosts file, your router's names), could still reach a private address there.
- **Made things show only pictures Open Sourcebook keeps.** A card, a quiz or a set of flashcards a maker writes may show only pictures Open Sourcebook stored (with their credit) or embeds; a web address is refused when it is written, removed when it is stored and not drawn. The web app has a content security policy: its scripts, pictures and media come only from Open Sourcebook itself, and it cannot be framed. A stored file opened by its own address runs nothing, and an SVG is a download.
- **The programs share secrets that the launcher makes.** On the first start, the launcher makes the strings the programs use to trust each other, with a secure random generator, and keeps them in `state/secrets.json` in the app data folder (`~/Library/Application Support/Open Sourcebook` on a Mac), readable only by you. Each program gets only the ones it needs; the scenes service gets a narrower token for the connector that starts turns only in its own folder. The engine's settings file `state/engine.env` is written at each start and holds copies of the keys in your `engine/.dev.vars`, also readable only by you. The browser and door keys are made new at each start and kept only in memory. `state/` is not committed. The folders where your projects are kept (`engine/.wrangler`, the scenes service's `.data`) are made readable only by you.
- **The agent's own tools are limited to a work folder.** When your agent makes a video it works in a folder of its own. On a plan alone it gets its file tools there and nothing else of its own: no shell and no web. With an API key it also gets its shell and the web, and on a Mac the whole agent then runs inside the operating system's sandbox. There it reads and writes its work folder and a temporary folder of its own, made fresh for each turn and removed when it ends. It can read, not write, the system's own folders and the folders its program and tools are installed in. The rest of your home folder (your documents, keys, other projects, other apps' data, your keychains and your agent's login), other drives, `/Users/Shared` and the shared temporary folders where other programs keep their files and sockets are shut to it. It can connect to no other program's socket on this computer (an ssh agent's, Docker's), only the system's name lookup, and to nothing on this computer's own address except the connector's port. It can reach the web, and the sandbox cannot tell other machines on your network apart from the web. Without a Mac's sandbox it does not get a shell.
- **Open Sourcebook never stores or forwards a subscription login.** It launches your own agent, the unmodified program signed in by you the normal way, and never reads, copies, stores, passes on or proxies that login. The only credentials Open Sourcebook may hold are API keys you chose to give it, in local files that are not committed (`engine/.dev.vars`, `services/scenes/.env`, and the copy in `state/engine.env`). This is a settled decision in [`docs/DECISIONS.md`](docs/DECISIONS.md) (the row on the agent's login).
- **Sources are untrusted.** What you drop in can contain anything. An answer's cites are checked word for word against your source, and an example file brought in is not trusted: every cite in it is found again in the text it brings.
- **The install writes into one folder.** The one-line install puts everything in `.opensourcebook` in your home folder, and outside it writes only what makes `opensourcebook` a command and a shortcut. It never asks for your password or administrator rights. A private copy of Node it downloads is checked against the checksum Node publishes. How it works is in [`install/README.md`](install/README.md).

## What Open Sourcebook does not protect against

- **Plain HTTP on your home network.** The phone's door is not encrypted. Someone who can watch your network's traffic can read what Open Sourcebook sends to a phone and take a device's cookie. Use it on a network you trust, not on public Wi-Fi.
- **Anything that runs as you, or as an administrator.** A program running under your own account can read the app data folder, your API keys and your browser's cookies, and an administrator of the computer can read anything. Open Sourcebook's keys keep out other people's accounts and programs that cannot read your files, not malware you are already running.
- **Other servers on this computer that your own browser opens.** Browsers send a cookie for `127.0.0.1` to every port there, so another local web server that your browser visits directly could receive Open Sourcebook's browser cookie (it changes at each start).
- **The opening address in the process list.** When a start or `opensourcebook open` opens your browser, the one-time address is briefly an argument of the program that opens it, which other accounts on the computer can see; it works once and for ten minutes.
- **The models themselves.** A source can try to talk your agent into doing something. Open Sourcebook limits what the agent's tools can reach, as above; how well a model resists being talked into misusing what it can reach has not been tested.
